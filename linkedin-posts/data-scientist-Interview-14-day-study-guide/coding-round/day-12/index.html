1. Precision, recall, F1

Python
What It Solves

Use zero guards for degenerate predictions.

Why This Is Best

This is the best interview solution because it uses the simplest pattern that reaches the target complexity, keeps edge cases visible, and leaves you with code you can explain line by line.

Complexity: Time: O(n) for a single pass unless the snippet sorts or builds a larger DP table. Space: O(n) when it stores counts, state, or output.
Example SolutionPython
def classification_metrics(y_true, y_pred):
    tp = sum(t == 1 and p == 1 for t, p in zip(y_true, y_pred))
    fp = sum(t == 0 and p == 1 for t, p in zip(y_true, y_pred))
    fn = sum(t == 1 and p == 0 for t, p in zip(y_true, y_pred))
    precision = tp / (tp + fp) if tp + fp else 0
    recall = tp / (tp + fn) if tp + fn else 0
    f1 = 2 * precision * recall / (precision + recall) if precision + recall else 0
    return {"precision": precision, "recall": recall, "f1": f1}

2. Train-test split

Python
What It Solves

Shuffle indices with a reproducible seed.

Why This Is Best

This is the best interview solution because it uses the simplest pattern that reaches the target complexity, keeps edge cases visible, and leaves you with code you can explain line by line.

Complexity: Time: O(n) for a single pass unless the snippet sorts or builds a larger DP table. Space: O(n) when it stores counts, state, or output.
Example SolutionPython
import numpy as np

def train_test_split(x, y, test_size=0.2, seed=42):
    rng = np.random.default_rng(seed)
    idx = rng.permutation(len(x))
    cut = int(len(x) * (1 - test_size))
    train_idx, test_idx = idx[:cut], idx[cut:]
    return x[train_idx], x[test_idx], y[train_idx], y[test_idx]

3. One gradient descent step

Python
What It Solves

Vectorized linear regression update.

Why This Is Best

This is the best interview solution because it uses the simplest pattern that reaches the target complexity, keeps edge cases visible, and leaves you with code you can explain line by line.

Complexity: Time: O(n) for a single pass unless the snippet sorts or builds a larger DP table. Space: O(n) when it stores counts, state, or output.
Example SolutionPython
import numpy as np

def gradient_step(X, y, w, b, lr):
    pred = X @ w + b
    err = pred - y
    dw = X.T @ err / len(y)
    db = err.mean()
    return w - lr * dw, b - lr * db

import numpy as np

def assign_clusters(X, centers):
    distances = ((X[:, None, :] - centers[None, :, :]) ** 2).sum(axis=2)
    return distances.argmin(axis=1)

5. Stratified sample indices

Python
What It Solves

Sample within each label to preserve class proportions.

Why This Is Best

This is the best interview solution because it uses the simplest pattern that reaches the target complexity, keeps edge cases visible, and leaves you with code you can explain line by line.

Complexity: Time: O(n) for a single pass unless the snippet sorts or builds a larger DP table. Space: O(n) when it stores counts, state, or output.
Example SolutionPython
import numpy as np

def stratified_sample(y, frac=0.2, seed=42):
    rng = np.random.default_rng(seed)
    selected = []
    for label in np.unique(y):
        idx = np.where(y == label)[0]
        n = max(1, int(len(idx) * frac))
        selected.extend(rng.choice(idx, size=n, replace=False))
    return np.array(selected)

6. Quartile buckets

SQL
What It Solves

NTILE is handy for segmentation.

Why This Is Best

This is the best approach because the window function ranks rows without collapsing detail. You can filter after ranking, handle ties intentionally, and avoid brittle nested subqueries that are harder to explain under pressure.

Complexity: Cost depends on table size, indexes, and partition cardinality; the important interview point is the row grain and join/window order.
Example SolutionSQL
SELECT user_id,
       revenue,
       NTILE(4) OVER (ORDER BY revenue DESC) AS revenue_quartile
FROM user_revenue;

7. Median with row numbers

SQL
What It Solves

Works in engines without a MEDIAN aggregate.

Why This Is Best

This is the best interview solution because it computes the metric at the correct grain, names the intermediate logic clearly, and handles edge cases such as nulls or zero denominators where they matter.

Complexity: Cost depends on table size, indexes, and partition cardinality; the important interview point is the row grain and join/window order.
Example SolutionSQL
WITH ranked AS (
  SELECT value,
         ROW_NUMBER() OVER (ORDER BY value) AS rn,
         COUNT(*) OVER () AS n
  FROM measurements
)
SELECT AVG(value) AS median_value
FROM ranked
WHERE rn IN ((n + 1) / 2, (n + 2) / 2);

8. Z-score outliers

SQL
What It Solves

Window stats let each row compare to the full distribution.

Why This Is Best

This is the best interview solution because it computes the metric at the correct grain, names the intermediate logic clearly, and handles edge cases such as nulls or zero denominators where they matter.

Complexity: Cost depends on table size, indexes, and partition cardinality; the important interview point is the row grain and join/window order.
Example SolutionSQL
SELECT user_id,
       metric_value,
       (metric_value - AVG(metric_value) OVER ()) /
       NULLIF(STDDEV(metric_value) OVER (), 0) AS z_score

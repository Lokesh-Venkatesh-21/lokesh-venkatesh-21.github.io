1. Frequency template

Python
What It Solves

A reusable skeleton for counting problems.

Why This Is Best

This is the best solution because the hash table stores exactly the information needed for constant-time lookup. It trades a small amount of memory for a clean O(n) pass and avoids repeated scans.

Complexity: Time: O(n) for a single pass unless the snippet sorts or builds a larger DP table. Space: O(n) when it stores counts, state, or output.
Example SolutionPython
from collections import Counter

def frequency_table(values):
    counts = Counter(values)
    return [{"value": value, "count": count} for value, count in counts.most_common()]

2. Two-pointer template

Python
What It Solves

Works after sorting when the target relation is monotonic.

Why This Is Best

This is the best interview solution because it uses the simplest pattern that reaches the target complexity, keeps edge cases visible, and leaves you with code you can explain line by line.

Complexity: Time: usually O(n log n) because of sorting. Space: O(n) or O(1), depending on output and language sort behavior.
Example SolutionPython
def pair_exists_sorted(nums, target):
    l, r = 0, len(nums) - 1
    while l < r:
        s = nums[l] + nums[r]
        if s == target:
            return True
        if s < target:
            l += 1
        else:
            r -= 1
    return False

3. BFS template

Python
What It Solves

Shortest unweighted traversal in one reusable pattern.

Why This Is Best

This is the best solution because it visits each node or cell once and records visited state explicitly. That gives predictable O(V + E) or O(rows * cols) behavior and avoids infinite loops in cyclic structures.

Complexity: Time: O(V + E) for graph inputs, or O(rows * cols) for grids. Space: O(V) for visited state.
Example SolutionPython
from collections import deque

def bfs_order(graph, start):
    q = deque([start])
    seen = {start}
    order = []
    while q:
        node = q.popleft()
        order.append(node)
        for nxt in graph.get(node, []):
            if nxt not in seen:
                seen.add(nxt)
                q.append(nxt)
    return order

4. Memoization template

Python
What It Solves

Use when recursive states repeat.

Why This Is Best

This is the best interview solution because it uses the simplest pattern that reaches the target complexity, keeps edge cases visible, and leaves you with code you can explain line by line.

Complexity: Time: O(n) for a single pass unless the snippet sorts or builds a larger DP table. Space: O(n) when it stores counts, state, or output.
Example SolutionPython
from functools import lru_cache

def count_ways(n):
    @lru_cache(None)
    def dp(i):
        if i == 0:
            return 1
        if i < 0:
            return 0
        return dp(i - 1) + dp(i - 2)
    return dp(n)

6. Window drill

SQL
What It Solves

Rank, previous value, and running total in one query.

Why This Is Best

This is the best interview solution because it computes the metric at the correct grain, names the intermediate logic clearly, and handles edge cases such as nulls or zero denominators where they matter.

Complexity: Cost depends on table size, indexes, and partition cardinality; the important interview point is the row grain and join/window order.
Example SolutionSQL
SELECT user_id,
       order_date,
       amount,
       ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY order_date) AS order_number,
       LAG(amount) OVER (PARTITION BY user_id ORDER BY order_date) AS previous_amount,
       SUM(amount) OVER (PARTITION BY user_id ORDER BY order_date) AS running_user_revenue
FROM orders;

7. Retention drill

SQL
What It Solves

Keep cohort, numerator, and denominator together.

Why This Is Best

This is the best interview shape because it keeps the cohort denominator visible, joins activity at the right grain, and makes the retention window explicit. That prevents the most common analytics bug: counting active users correctly but dividing by the wrong base.

Complexity: Cost depends on table size, indexes, and partition cardinality; the important interview point is the row grain and join/window order.
Example SolutionSQL
SELECT s.signup_date,
       COUNT(DISTINCT s.user_id) AS cohort_size,
       COUNT(DISTINCT a.user_id) AS retained_users,
       COUNT(DISTINCT a.user_id)::float / NULLIF(COUNT(DISTINCT s.user_id), 0) AS retention
FROM signups s
LEFT JOIN activity a
  ON a.user_id = s.user_id
 AND a.activity_date BETWEEN s.signup_date + INTERVAL '1 day'
                         AND s.signup_date + INTERVAL '7 day'
GROUP BY s.signup_date;

8. Final metric QA

SQL
What It Solves

Compare row counts, users, and value totals before trusting a result.

Why This Is Best

This is the best interview solution because it computes the metric at the correct grain, names the intermediate logic clearly, and handles edge cases such as nulls or zero denominators where they matter.

Complexity: Cost depends on table size, indexes, and partition cardinality; the important interview point is the row grain and join/window order.
Example SolutionSQL
SELECT COUNT(*) AS rows,
       COUNT(DISTINCT user_id) AS users,
       SUM(amount) AS total_amount,
       MIN(order_date) AS first_order,
       MAX(order_date) AS last_order
FROM orders
WHERE status = 'paid';

1. Generate subsets

Python
What It Solves

Choose or skip each item.

Why This Is Best

This is the best interview solution because it uses the simplest pattern that reaches the target complexity, keeps edge cases visible, and leaves you with code you can explain line by line.

Complexity: Time: O(n) for a single pass unless the snippet sorts or builds a larger DP table. Space: O(n) when it stores counts, state, or output.
Example SolutionPython
def subsets(nums):
    out = []
    path = []
    def dfs(i):
        if i == len(nums):
            out.append(path[:])
            return
        dfs(i + 1)
        path.append(nums[i])
        dfs(i + 1)
        path.pop()
    dfs(0)
    return out

2. Generate permutations

Python
What It Solves

Track used positions to avoid reusing values.

Why This Is Best

This is the best interview solution because it uses the simplest pattern that reaches the target complexity, keeps edge cases visible, and leaves you with code you can explain line by line.

Complexity: Time: O(n) for a single pass unless the snippet sorts or builds a larger DP table. Space: O(n) when it stores counts, state, or output.
Example SolutionPython
def permutations(nums):
    out, path, used = [], [], [False] * len(nums)
    def dfs():
        if len(path) == len(nums):
            out.append(path[:])
            return
        for i, x in enumerate(nums):
            if used[i]:
                continue
            used[i] = True
            path.append(x)
            dfs()
            path.pop()
            used[i] = False
    dfs()
    return out

3. Climbing stairs with memo

Python
What It Solves

Memoization turns exponential recursion into linear time.

Why This Is Best

This is the best interview solution because it uses the simplest pattern that reaches the target complexity, keeps edge cases visible, and leaves you with code you can explain line by line.

Complexity: Time: O(n) for a single pass unless the snippet sorts or builds a larger DP table. Space: O(n) when it stores counts, state, or output.
Example SolutionPython
from functools import lru_cache

def climb_stairs(n):
    @lru_cache(None)
    def ways(i):
        if i <= 2:
            return i
        return ways(i - 1) + ways(i - 2)
    return ways(n)

4. Flatten nested list

What It Solves

Example SolutionPython
def flatten(values):
    for value in values:
        if isinstance(value, list):
            yield from flatten(value)
        else:
            yield value

5. Combination sum

Python
What It Solves

Reuse the same index when repeats are allowed.

Why This Is Best

This is the best interview solution because it uses the simplest pattern that reaches the target complexity, keeps edge cases visible, and leaves you with code you can explain line by line.

Complexity: Time: O(n) for a single pass unless the snippet sorts or builds a larger DP table. Space: O(n) when it stores counts, state, or output.
Example SolutionPython
def combination_sum(candidates, target):
    out, path = [], []
    def dfs(start, remaining):
        if remaining == 0:
            out.append(path[:]); return
        for i in range(start, len(candidates)):
            x = candidates[i]
            if x <= remaining:
                path.append(x)
                dfs(i, remaining - x)
                path.pop()
    dfs(0, target)
    return out

6. Top order per customer

SQL
What It Solves

ROW_NUMBER chooses exactly one row per group.

Why This Is Best

This is the best approach because the window function ranks rows without collapsing detail. You can filter after ranking, handle ties intentionally, and avoid brittle nested subqueries that are harder to explain under pressure.

Complexity: Cost depends on table size, indexes, and partition cardinality; the important interview point is the row grain and join/window order.
Example SolutionSQL
WITH ranked AS (
  SELECT *,
         ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY amount DESC, order_id) AS rn
  FROM orders
)
SELECT *
FROM ranked
WHERE rn = 1;

8. Nth purchase per user

SQL
What It Solves

Filter row_number after sequencing events.

Why This Is Best

This is the best approach because the window function ranks rows without collapsing detail. You can filter after ranking, handle ties intentionally, and avoid brittle nested subqueries that are harder to explain under pressure.

Complexity: Cost depends on table size, indexes, and partition cardinality; the important interview point is the row grain and join/window order.
Example SolutionSQL
WITH purchases AS (
  SELECT user_id,
         order_id,
         order_date,
         ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY order_date) AS purchase_number
  FROM orders
)
SELECT *
FROM purchases
WHERE purchase_number = 3;

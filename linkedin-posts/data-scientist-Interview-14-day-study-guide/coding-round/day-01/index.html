1. Two Sum with a hash map

Python
What It Solves

One pass, O(n) time, O(n) space.

Why This Is Best

This is the best solution because the hash table stores exactly the information needed for constant-time lookup. It trades a small amount of memory for a clean O(n) pass and avoids repeated scans.

Complexity: Time: O(n) for a single pass unless the snippet sorts or builds a larger DP table. Space: O(n) when it stores counts, state, or output.
Example SolutionPython
def two_sum(nums, target):
    seen = {}
    for i, x in enumerate(nums):
        need = target - x
        if need in seen:
            return [seen[need], i]
        seen[x] = i
    return []

Counter handles repeated characters without sorting.

Why This Is Best

This is the best solution because the hash table stores exactly the information needed for constant-time lookup. It trades a small amount of memory for a clean O(n) pass and avoids repeated scans.

Complexity: Time: usually O(n log n) because of sorting. Space: O(n) or O(1), depending on output and language sort behavior.
Example SolutionPython
from collections import Counter

def is_anagram(a, b):
    return len(a) == len(b) and Counter(a) == Counter(b)

3. First non-repeating character

Python
What It Solves

Count once, then scan once. Avoid s.count inside a loop.

Why This Is Best

This is the best interview solution because it uses the simplest pattern that reaches the target complexity, keeps edge cases visible, and leaves you with code you can explain line by line.

Complexity: Time: O(n) for a single pass unless the snippet sorts or builds a larger DP table. Space: O(n) when it stores counts, state, or output.
Example SolutionPython
from collections import Counter

def first_unique_char(s):
    counts = Counter(s)
    for i, ch in enumerate(s):
        if counts[ch] == 1:
            return i
    return -1

4. Deduplicate while preserving order

Python
What It Solves

Useful for event streams and feature lists.

Why This Is Best

This is the best solution because the hash table stores exactly the information needed for constant-time lookup. It trades a small amount of memory for a clean O(n) pass and avoids repeated scans.

Complexity: Time: O(n) for a single pass unless the snippet sorts or builds a larger DP table. Space: O(n) when it stores counts, state, or output.
Example SolutionPython
def dedupe_ordered(values):
    seen = set()
    out = []
    for value in values:
        if value not in seen:
            seen.add(value)
            out.append(value)
    return out

5. Top category by frequency

Common in exploratory data checks.

Complexity: Time: O(n) for a single pass unless the snippet sorts or builds a larger DP table. Space: O(n) when it stores counts, state, or output.
Example SolutionPython
from collections import Counter

def most_common_category(rows, key):
    counts = Counter(row[key] for row in rows)
    return counts.most_common(1)[0] if counts else None

6. Users with zero orders

SQL
What It Solves

Count the right-side key so unmatched rows count as zero.

Why This Is Best

This is the best approach because the LEFT JOIN keeps unmatched entities in the result before the final filter. It makes missing behavior explicit and avoids accidentally turning the query into an INNER JOIN.

Complexity: Cost depends on table size, indexes, and partition cardinality; the important interview point is the row grain and join/window order.
Example SolutionSQL
SELECT u.user_id
FROM users u
LEFT JOIN orders o
  ON o.user_id = u.user_id
GROUP BY u.user_id
HAVING COUNT(o.order_id) = 0;

7. Revenue by country

SQL
What It Solves

Filter rows before grouping; aggregate after.

Why This Is Best

This is the best interview solution because it computes the metric at the correct grain, names the intermediate logic clearly, and handles edge cases such as nulls or zero denominators where they matter.

Complexity: Cost depends on table size, indexes, and partition cardinality; the important interview point is the row grain and join/window order.
Example SolutionSQL
SELECT u.country,
       SUM(o.amount) AS revenue
FROM orders o
JOIN users u
  ON u.user_id = o.user_id
WHERE o.status = 'paid'
GROUP BY u.country
ORDER BY revenue DESC;

8. Average order value

SQL
What It Solves

Use NULLIF to avoid divide-by-zero when reused in wider reports.

Why This Is Best

This is the best interview solution because it computes the metric at the correct grain, names the intermediate logic clearly, and handles edge cases such as nulls or zero denominators where they matter.

Complexity: Cost depends on table size, indexes, and partition cardinality; the important interview point is the row grain and join/window order.
Example SolutionSQL
SELECT DATE_TRUNC('month', order_date) AS month,
       SUM(amount) / NULLIF(COUNT(order_id), 0) AS aov
FROM orders
WHERE status = 'paid'
GROUP BY 1
ORDER BY 1;

1. Pandas groupby aggregation

What It Solves

Named aggregations produce clean column names.

Why This Is Best

This is the best solution because it uses vectorized dataframe or array operations instead of row-by-row Python loops. That is the production-friendly pattern for data science work: clearer intent and much better performance.

Complexity: Time: O(n) for a single pass unless the snippet sorts or builds a larger DP table. Space: O(n) when it stores counts, state, or output.
Example SolutionPython
def revenue_by_country(orders, users):
    df = orders.merge(users[["user_id", "country"]], on="user_id", how="left")
    return (
        df.groupby("country", as_index=False)
          .agg(revenue=("amount", "sum"), orders=("order_id", "nunique"))
    )

5. NumPy standardization

Python
What It Solves

Fit statistics on train data, then transform.

Why This Is Best

This is the best solution because it uses vectorized dataframe or array operations instead of row-by-row Python loops. That is the production-friendly pattern for data science work: clearer intent and much better performance.

Complexity: Time: O(n) for a single pass unless the snippet sorts or builds a larger DP table. Space: O(n) when it stores counts, state, or output.
Example SolutionPython
import numpy as np

def standardize_train_test(x_train, x_test):
    mean = x_train.mean(axis=0)
    std = x_train.std(axis=0)
    std = np.where(std == 0, 1, std)
    return (x_train - mean) / std, (x_test - mean) / std

6. DAU to MAU ratio

SQL
What It Solves

Align daily users with a rolling 30-day active base.

Why This Is Best

This is the best interview solution because it computes the metric at the correct grain, names the intermediate logic clearly, and handles edge cases such as nulls or zero denominators where they matter.

Complexity: Cost depends on table size, indexes, and partition cardinality; the important interview point is the row grain and join/window order.
Example SolutionSQL
WITH days AS (
  SELECT DISTINCT activity_date AS day FROM activity
)
SELECT d.day,
       COUNT(DISTINCT CASE WHEN a.activity_date = d.day THEN a.user_id END) AS dau,
       COUNT(DISTINCT a.user_id) AS mau_30d,
       COUNT(DISTINCT CASE WHEN a.activity_date = d.day THEN a.user_id END)::float /
       NULLIF(COUNT(DISTINCT a.user_id), 0) AS dau_mau
FROM days d
JOIN activity a
  ON a.activity_date BETWEEN d.day - INTERVAL '29 day' AND d.day
GROUP BY d.day;

7. Monthly churn

SQL
What It Solves

Users active last month but absent this month.

Why This Is Best

This is the best approach because the window function ranks rows without collapsing detail. You can filter after ranking, handle ties intentionally, and avoid brittle nested subqueries that are harder to explain under pressure.

Complexity: Cost depends on table size, indexes, and partition cardinality; the important interview point is the row grain and join/window order.
Example SolutionSQL
WITH monthly AS (
  SELECT DISTINCT user_id, DATE_TRUNC('month', activity_date) AS month
  FROM activity
)
SELECT last.month + INTERVAL '1 month' AS month,
       COUNT(DISTINCT last.user_id) AS previous_active,
       COUNT(DISTINCT CASE WHEN curr.user_id IS NULL THEN last.user_id END) AS churned
FROM monthly last
LEFT JOIN monthly curr
  ON curr.user_id = last.user_id
 AND curr.month = last.month + INTERVAL '1 month'
GROUP BY 1;

8. ARPU by month

SQL
What It Solves

Revenue divided by active users at the same grain.

Why This Is Best

This is the best approach because the window function ranks rows without collapsing detail. You can filter after ranking, handle ties intentionally, and avoid brittle nested subqueries that are harder to explain under pressure.

Complexity: Cost depends on table size, indexes, and partition cardinality; the important interview point is the row grain and join/window order.
Example SolutionSQL
WITH monthly_revenue AS (
  SELECT DATE_TRUNC('month', order_date) AS month, SUM(amount) AS revenue
  FROM orders
  GROUP BY 1
),
monthly_active AS (
  SELECT DATE_TRUNC('month', activity_date) AS month, COUNT(DISTINCT user_id) AS active_users
  FROM activity
  GROUP BY 1
)
SELECT r.month,
       r.revenue / NULLIF(a.active_users, 0) AS arpu
FROM monthly_revenue r
JOIN monthly_active a USING (month);

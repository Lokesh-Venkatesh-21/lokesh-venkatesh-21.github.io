1. House robber

Why This Is Best

This is the best solution because it defines a compact state, reuses previous work, and avoids exponential recomputation. Where possible, the state is compressed so the code is both fast and interview-readable.

Complexity: Time: O(n) for a single pass unless the snippet sorts or builds a larger DP table. Space: O(n) when it stores counts, state, or output.
Example SolutionPython
def rob(nums):
    prev2 = prev1 = 0
    for x in nums:
        prev2, prev1 = prev1, max(prev1, prev2 + x)
    return prev1

2. Coin change

Python
What It Solves

Unbounded knapsack over amounts.

Why This Is Best

This is the best solution because it defines a compact state, reuses previous work, and avoids exponential recomputation. Where possible, the state is compressed so the code is both fast and interview-readable.

Complexity: Time and space follow the DP state size; explain the state dimensions before giving Big-O.
Example SolutionPython
def coin_change(coins, amount):
    dp = [float("inf")] * (amount + 1)
    dp[0] = 0
    for a in range(1, amount + 1):
        for coin in coins:
            if coin <= a:
                dp[a] = min(dp[a], dp[a - coin] + 1)
    return -1 if dp[amount] == float("inf") else dp[amount]

3. Longest increasing subsequence

Python
What It Solves

Patience sorting keeps candidate tails.

Why This Is Best

This is the best interview solution because it uses the simplest pattern that reaches the target complexity, keeps edge cases visible, and leaves you with code you can explain line by line.

Complexity: Time: usually O(n log n) because of sorting. Space: O(n) or O(1), depending on output and language sort behavior.
Example SolutionPython
import bisect

def length_of_lis(nums):
    tails = []
    for x in nums:
        i = bisect.bisect_left(tails, x)
        if i == len(tails):
            tails.append(x)
        else:
            tails[i] = x
    return len(tails)

4. Decode ways

Python
What It Solves

State is the number of ways to parse up to each index.

Why This Is Best

This is the best solution because it defines a compact state, reuses previous work, and avoids exponential recomputation. Where possible, the state is compressed so the code is both fast and interview-readable.

Complexity: Time: O(n) for a single pass unless the snippet sorts or builds a larger DP table. Space: O(n) when it stores counts, state, or output.
Example SolutionPython
def num_decodings(s):
    if not s or s[0] == "0":
        return 0
    prev2, prev1 = 1, 1
    for i in range(1, len(s)):
        cur = 0
        if s[i] != "0":
            cur += prev1
        if 10 <= int(s[i-1:i+1]) <= 26:
            cur += prev2
        prev2, prev1 = prev1, cur
    return prev1

5. Maximum subarray

Python
What It Solves

Kadane's algorithm chooses extend vs restart.

Why This Is Best

This is the best solution because it defines a compact state, reuses previous work, and avoids exponential recomputation. Where possible, the state is compressed so the code is both fast and interview-readable.

Complexity: Time: O(n) for a single pass unless the snippet sorts or builds a larger DP table. Space: O(n) when it stores counts, state, or output.
Example SolutionPython
def max_subarray(nums):
    best = cur = nums[0]
    for x in nums[1:]:
        cur = max(x, cur + x)
        best = max(best, cur)
    return best

6. Monthly cohort retention grid

SQL
What It Solves

Period number is activity month minus cohort month.

Why This Is Best

This is the best interview shape because it keeps the cohort denominator visible, joins activity at the right grain, and makes the retention window explicit. That prevents the most common analytics bug: counting active users correctly but dividing by the wrong base.

Complexity: Cost depends on table size, indexes, and partition cardinality; the important interview point is the row grain and join/window order.
Example SolutionSQL
WITH cohorts AS (
  SELECT user_id, DATE_TRUNC('month', MIN(signup_date)) AS cohort_month
  FROM users
  GROUP BY user_id
),
activity_months AS (
  SELECT DISTINCT user_id, DATE_TRUNC('month', activity_date) AS activity_month
  FROM activity
)
SELECT c.cohort_month,
       ((EXTRACT(YEAR FROM a.activity_month) - EXTRACT(YEAR FROM c.cohort_month)) * 12
        + EXTRACT(MONTH FROM a.activity_month) - EXTRACT(MONTH FROM c.cohort_month)) AS period,
       COUNT(DISTINCT a.user_id) AS active_users
FROM cohorts c
JOIN activity_months a USING (user_id)
GROUP BY 1, 2;

7. Cohort revenue curve

SQL
What It Solves

Cumulative revenue by cohort and period.

Why This Is Best

This is the best interview shape because it keeps the cohort denominator visible, joins activity at the right grain, and makes the retention window explicit. That prevents the most common analytics bug: counting active users correctly but dividing by the wrong base.

Complexity: Cost depends on table size, indexes, and partition cardinality; the important interview point is the row grain and join/window order.
Example SolutionSQL
WITH cohorts AS (
  SELECT user_id, DATE_TRUNC('month', MIN(signup_date)) AS cohort_month
  FROM users GROUP BY user_id
)
SELECT c.cohort_month,
       DATE_TRUNC('month', o.order_date) AS revenue_month,
       SUM(SUM(o.amount)) OVER (
         PARTITION BY c.cohort_month
         ORDER BY DATE_TRUNC('month', o.order_date)
       ) AS cumulative_revenue
FROM cohorts c
JOIN orders o USING (user_id)
GROUP BY 1, 2;
